# 集客と営業の仕組み

週12時間のうち、営業に割けるのは**月8時間**しかない。
この制約下で月2〜3件を受注し続けるための設計。

---

## 全体像: 3層構造

```
                     0ヶ月目から効く          3ヶ月目から          6ヶ月目から
                  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐
                  │  L1 アウト   │  │  L2 実証     │  │  L3 紹介     │
                  │  バウンド     │  │  コンテンツ   │  │              │
                  └───────┬──────┘  └───────┬──────┘  └───────┬──────┘
   受注に占める割合    100% ──→ 60%       0% ──→ 25%       0% ──→ 15%
   1件あたりの工数     2.5時間          0.5時間          0.2時間
   立ち上がり          即日             3ヶ月            6ヶ月
```

**L1だけで日給10万円まで到達できる。** L2とL3は、L1の工数を下げるために後から足す。
最初からL2・L3に手を出すと、成果が出る前に資金と気力が尽きる。

---

## L1: アウトバウンド（主力・初日から効く）

### なぜアウトバウンドなのか

インバウンド（SEO・広告・SNS）は、**成果が出るまで自分では制御できない**。
アウトバウンドは、送った通数に比例して商談が発生する。
資金100万円・週12時間という条件では、制御できることだけに賭けるべき。

実測の目安:

```
  800通送信  ──90%到達──▶  720通着信
              ──5%返信───▶   36件返信
              ──35%前向き─▶   12件が前向き
              ──70%商談化─▶    8件の商談
              ──25%成約───▶    2件の受注
```

**1受注あたり約360通**。月800通で月2件。これが `financial_model.py` の前提になっている。
この数字は `python3 -m cashman dashboard` の「1件受注に必要な送信数」で実測に置き換わる。

### リストの作り方: 求人を起点にする

このシステムの中核は、**「求人票 = 困っている証拠」** という一点にある。

求人を出している会社は、次の3つを同時に公開している。

1. **どの業務が回っていないか**（職種名）
2. **どう回っていないか**（業務内容欄の「Excelに手入力」「目視で突合」）
3. **予算があること**（人を採る金があるなら、自動化する金もある）

これほど質の高いシグナルが公開・無料で取れる領域は他にない。
`src/cashman/signals.py` はこの求人票からシグナルを抽出する。

#### 実際に使う情報源

| 情報源 | 取れるもの | 取得方法 | コスト |
|---|---|---|---|
| 求人サイト（Indeed / 求人ボックス等） | 職種・業務内容・所在地 | 各サイトの利用規約を確認し、許容される範囲で取得 | 無料 |
| ハローワークインターネットサービス | 職種・従業員数・業務内容 | 検索結果をCSVで保存 | 無料 |
| 国税庁 法人番号公表サイト | 正式名称・所在地・法人番号 | Web-API（無料・登録制） | 無料 |
| 官報・PR TIMES | 資金調達・新規事業 | RSS | 無料 |
| 各社の採用ページ | 業務内容の詳細・問い合わせ先 | 直接閲覧 | 無料 |

**スクレイピングは各サイトの利用規約と robots.txt に従うこと。**
規約で禁じられている場合は、手動収集か、規約上明示的に許可されたAPI・
データ提供サービスを使う。ここで規約違反をすると、事業ごと止まるリスクがある。

#### リスト作成は自分でやらない（重要）

必要なのは1日40〜60社、月にすると800〜1,200社。1社あたり2分かかるので、
**自分でやると月27〜40時間**になる。営業に割ける月8時間を大きく超えるため、
この設計は成立しない。

**リスト作成は最初から外注する。** これが資金100万円の最も効率のいい使い道になる。

| 項目 | 内容 |
|---|---|
| 発注先 | クラウドソーシング（クラウドワークス / ランサーズ等） |
| 単価 | 1社あたり20〜30円 |
| 月間コスト | 月1,000社で**2〜3万円** |
| 浮く時間 | **月30時間以上** |

`financial_model.py` の `Costs.list_building_monthly` がこの費用を持つ。
反映しても日給10万円の到達は11ヶ月目のまま変わらず、資金の谷底が2万円下がるだけ。
**月2.5万円で月30時間を買える**ので、判断としては明白。

#### 外注に渡す作業指示

外注先に渡すのは「判断のいらない手順」だけにする。判断が入ると品質がばらつく。

```
1. 求人サイトで下記の条件で検索する
     職種キーワード: 営業事務 / 受発注 / データ入力 / 経理アシスタント
     地域: 東京都・神奈川県・埼玉県・千葉県
     掲載日: 直近30日以内
2. 各求人について、以下をスプレッドシートに記入する
     - 会社名（求人票に記載のとおり正確に）
     - 会社の公式サイトURL
     - サイトに公開されている問い合わせ用メールアドレス
       ※ info@ contact@ sales@ recruit@ のような代表アドレスのみ。
         個人名のアドレス（yamada@ 等）は記入しない
     - そのアドレスが掲載されているページのURL   ← 必ず記入
     - 業種 / 従業員数 / 所在地（会社概要ページから）
     - 求人の職種名（そのまま）
     - 業務内容欄の本文（そのままコピー）   ← 省略しない
     - 求人URL / 掲載日
3. 従業員数が30人未満、または300人超の会社は記入しない
4. 学校・官公庁・宗教法人は記入しない
```

**2つの指示が特に重要。**

- **「アドレスの掲載ページURLを必ず記入」** — 特定電子メール法の適用除外
  （公表アドレスであること）を後から示せるのは、この記録だけになる（→ `docs/04-legal.md`）
- **「業務内容欄をそのままコピー、省略しない」** — ここに「Excelに手入力」「目視で突合」
  といった語が入っており、シグナル抽出もメール一行目の引用もすべてこの本文から作られる。
  要約されると、このシステムの中核が死ぬ

納品されたスプレッドシートをCSVで書き出し、そのまま `ingest` に流す。
スコアリングで45点未満は自動的に落ちるので、外注側で選別の判断をさせる必要はない。

#### 品質管理

初回は**50社だけ発注して検品する**。上記4項目が守られているかを確認し、
守れている人にだけ継続発注する。ここで妥協すると、以降数ヶ月の返信率が下がり続ける。

#### CSVの形式

`data/sample_leads.csv` と同じ列で `python3 -m cashman ingest` に流し込む。

```csv
name,domain,email,industry,employees,prefecture,job_title,job_body,job_url,posted_at
株式会社山田物流,yamada-logi.jp,info@yamada-logi.jp,物流,120,東京都,営業事務（受発注管理）,受注メールをExcelへ手入力し基幹システムへ転記。目視で突合。,https://...,2026-09-05
```

### 誰に送るか: スコアリング

`src/cashman/signals.py` が100点満点で採点する。**45点未満には送らない。**

| 加点 | 点 | 理由 |
|---|---|---|
| 従業員50〜200人 | +25 | 担当者と決裁者の距離が近い。商談1〜2回で決まる |
| 従業員30〜300人 | +15 | 対象帯 |
| 注力業種 | +15 | 事例が効く |
| 資金調達の公表 | +35 | 予算があり、急いでいる |
| 事務・オペ職の募集 | +30 | その業務が人手で回っている |
| 同一職種の繰り返し募集 | +25 | 採用では解決しなかった業務。最も刺さる |
| 求人票に「Excel / 手入力 / 転記 / 目視」 | +25 | 自動化余地が具体的に書かれている |

| 減点 | 点 | 理由 |
|---|---|---|
| 従業員30人未満 | -20 | 月額15万円の予算が無い |
| 従業員300人超 | -10 | 決裁に半年かかる。副業の時間では追えない |
| 除外業種（官公庁・学校・宗教） | -60 | 調達プロセスが特殊で個人事業では入れない |
| **シグナルが1つも無い** | **-40** | 一行目が書けない相手は返信もしない |

シグナルは**45日で効果が半減する**（`signals.decay()`）。
半年前の求人は今の課題を表していないため、古いリードは自動的に圏外に落ちる。

### 何を送るか: 4通のシーケンス

**返信の6〜7割は2通目以降に来る。** 1通で諦めると母数の大半を捨てることになる。
`src/cashman/compose.py` の `SEQUENCE` がこれを持っている。

| 通 | 送信日 | 角度 | 依頼の大きさ |
|---|---|---|---|
| 1 | Day 0 | 観測したシグナルを引用し、仮説を1つ置く | 資料を送ってよいか |
| 2 | Day 3 | 同業・同規模の事例を数字付きで1本 | なし（情報提供のみ） |
| 3 | Day 8 | 依頼をさらに小さくする（資料 → 試算1枚） | 試算を作ってよいか |
| 4 | Day 16 | クローズを宣言する | なし |

**4通目（ブレイクアップ）の返信率が最も高い**ことが多い。
「もう送りません」と言われて初めて、人は返事を書く。

#### 文面の3原則

1. **一行目で「あなたを個別に調べた」ことを示す。**
   テンプレ感が出た瞬間に読まれない。シグナルをそのまま引用する。

   > 「営業事務（受発注管理）」を90日で2回募集、という貴社の公開情報を拝見してご連絡しました。

2. **初回で商談を求めない。**
   「30分お時間を」は返信率を半分以下にする。
   Yes/Noが1秒で決まる依頼まで落とす → 「資料希望、とだけご返信ください」

3. **数字を創作しない。**
   実績が無いうちは「月80時間を3時間に」は自社の想定値として書き、
   事例ができたら実名・実数に差し替える。嘘は1回で全部を失う。

### いつ送るか: ウォームアップを守る

**新規ドメインで初日から40通送ると、数日で焼ける。** 一度焼けたドメインは二度と使えない。

| 期間 | 1日の上限 |
|---|---|
| Day 1-3 | 5通 |
| Day 4-7 | 10通 |
| Day 8-14 | 20通 |
| Day 15-21 | 30通 |
| Day 22〜 | 40通 |

`src/cashman/sender.py` がこれを強制する。CLIから超えることはできない。

**営業用ドメインは本番と必ず分ける。** 本番が `example.co.jp` なら営業は `example-jp.com`。
焼けても本業のメールが届かなくなる事故を防ぐ。

送信前に必須の設定:
- SPF / DKIM / DMARC（未設定だと到達率が半分以下になる）
- `mail-tester.com` で9点以上
- 送信間隔をランダムに8〜45秒空ける（`sender.send_due()` が自動でやる）

### 数字が悪いときにどこを直すか

**直す順番を固定しておく。** 手当たり次第に触ると何が効いたか分からなくなる。

| 症状 | 疑う場所 | 打ち手 |
|---|---|---|
| 到達率が低い（迷惑メール行き） | ドメイン設定 | SPF/DKIM/DMARC を確認。ウォームアップをやり直す |
| **返信率 2%未満** | **ターゲット** | 文面は触らない。業種・規模・シグナル種別を変える |
| 返信は来るが前向きが少ない | オファー | 価格ではなく「誰の何の業務か」の具体性を上げる |
| 商談は入るが受注しない | 提案 | 無料の試算提供に切り替える。決裁者が同席しているか確認 |
| 配信停止率 2%超 | リストか文面 | ICPから外れた相手に送っている。スコア閾値を上げる |

**返信率が低いとき文面をいじるのは、ほぼ必ず間違い。**
返信率への影響は「誰に送るか」が8割、「何を書くか」が2割。

`python3 -m cashman dashboard` は、シグナル種別ごとの返信率（`calibrate()`）も出す。
送信30通を超えたシグナルについて、平均比で何倍効いているかが分かるので、
効いているシグナルにリストを寄せる。

## L2: 実証コンテンツ（3ヶ月目から）

SEOブログは除外指定だが、**「検索流入を狙わないコンテンツ」は別物**として扱う。

### やること: 自分の数字を全部公開する

X（Twitter）とnoteで、この事業の数字をそのまま出す。

- 「今月 812通送って、返信41件、商談9件、受注2件でした」
- 「返信率が3.2%から5.1%に上がった理由は、業種を物流に絞ったからでした」
- 「月92時間の転記作業を4時間にした実装を全部書きます」

### なぜSEOと違って効くのか

| | SEOブログ | 実証コンテンツ |
|---|---|---|
| 成果までの期間 | 12〜18ヶ月 | 3ヶ月 |
| 必要な本数 | 100本以上 | 週1本 × 12本 |
| 競合 | 資本のある事業者と正面衝突 | 自分の実データは誰も持っていない |
| 読者 | 検索する人（≠決裁者） | 同業の経営者・決裁者が多い |
| 週12時間での実現性 | 不可能 | 週1時間で回る |

**週1本・1時間**。アウトバウンドで実際に起きたことを書くだけなので、ネタ切れしない。

### 効果の出方

3ヶ月目あたりから、アウトバウンドの返信に「note見ました」が混ざり始める。
これが起きると**同じ文面のままで返信率が1.3〜1.5倍になる**。
コンテンツ単体で集客するのではなく、**アウトバウンドの成約率を上げる装置**として使う。

## L3: 紹介（6ヶ月目から）

### 仕組みとして組み込む

「紹介してください」と頼むのではなく、**契約に組み込む**。

| タイミング | やること |
|---|---|
| 導入1ヶ月後 | 削減できた時間の実測レポートを提出する（自動生成） |
| 導入3ヶ月後 | レポートと合わせて「同じ課題を持つ会社をご存じですか」と1回だけ聞く |
| 紹介が成立 | 紹介元の翌月分を無料にする |

**聞くのは3ヶ月後の1回だけ。** 効果が数字で見えた直後が最も紹介が出る。
何度も聞くと関係が悪くなる。

### 紹介が最強である理由

- 商談化率が80%以上（アウトバウンドは2%）
- 成約率が60%以上（アウトバウンドは25%）
- 値引き交渉がほぼ起きない
- 工数は1件あたり0.2時間

顧客20社で年間6〜8件の紹介が出れば、**アウトバウンドの1/3を代替できる**。
これが10ヶ月目の工数の壁を先送りする唯一の手段になる。

## 商談の型（受注率を25%に乗せる）

週12時間では、**1社あたり商談30分 × 1回で決める**必要がある。
2回目を設定した時点で、受注率は下がり工数は倍になる。

### 30分の配分

| 時間 | やること | 目的 |
|---|---|---|
| 0-5分 | 現状のヒアリング（誰が・週何時間・何を使って） | 数字を引き出す |
| 5-10分 | その場で金額に換算して読み上げる | 「月16万円かかっています」と言語化する |
| 10-20分 | 自動化後の姿を具体的に説明 | 抽象的な「AI導入」ではなく、画面と手順で話す |
| 20-25分 | 価格と期間を提示 | その場で出す。持ち帰ると失注率が上がる |
| 25-30分 | 次の一歩を1つだけ決める | 「来週金曜までにご返答」まで握る |

### 必ず確認する3点

1. **決裁者は誰か。** 担当者だけの商談は、受注率が1/3になる。
   「導入を決めるのはどなたですか」を5分以内に聞く。
2. **いつまでに解決したいか。** 期限が無い案件は永久に決まらない。
3. **今その業務を誰がやっているか。** 自動化で仕事が無くなる人が同席していると、必ず止まる。

### 価格は必ずその場で出す

見積もりを持ち帰ると、検討期間に競合が入るか、優先度が下がる。
`docs/02-offer.md` の価格表を暗記しておき、その場で提示する。
