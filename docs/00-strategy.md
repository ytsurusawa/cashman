# 戦略: 日給100万円までの最短ルート

## 結論

| マイルストーン | 到達時期 | 状態 |
|---|---|---|
| 初受注 | 2〜3ヶ月目 | 副業のまま |
| 日給3万円（月粗利90万） | 3〜4ヶ月目 | 副業のまま |
| **日給10万円（月粗利300万）** | **11ヶ月目** | 副業の限界点。専業化の判断 |
| 日給30万円（月粗利900万） | 13〜15ヶ月目 | 専業＋単価引き上げ |
| **日給100万円（月粗利3,000万）** | **31ヶ月目（2年7ヶ月）** | 5〜8人のチーム |

この数字は `financial_model.py --phased` の出力そのもの。前提を変えれば数字も変わる。

```
python3 financial_model.py --phased
```

**日給100万円を1年で、という設計は作れない。** 月粗利3,000万円は年商換算で4〜5億円規模であり、
週12時間の個人が1年で到達した事例は、少なくとも再現可能な形では存在しない。
2年7ヶ月という数字ですら、下記の前提が全部当たった場合の値になる。

---

## 最も重要な発見: 効くのは単価だけ

前提を1つずつ動かして、日給10万円への到達月がどう変わるかを測った。

| 条件 | 日給10万円への到達 |
|---|---|
| 基準（返信率5% / 解約3% / 月額15万） | 11ヶ月目 |
| 返信率が半分（2.5%） | 30ヶ月目 |
| 解約が倍（6%/月） | 13ヶ月目 |
| **単価が半分（月額7.5万）** | **36ヶ月以内に未到達** |
| **単価が2倍（月額30万）** | **6ヶ月目** |
| 最悪（返信2.5% + 解約6% + 単価半分） | 未到達 |

再現コマンド:

```
python3 financial_model.py --mrr 75000    # 単価半分
python3 financial_model.py --mrr 300000   # 単価2倍
```

読み取れることは3つ。

1. **単価がすべてを支配する。** 半分にすると永久に届かず、2倍にすると5ヶ月早まる。
   努力の総量ではなく、1社からいくら貰えるかで結果が決まる。
2. **解約率は思ったより効かない。** 月3%が6%になっても2ヶ月しかずれない。
   解約対策に時間を使うくらいなら、単価交渉に使うほうが効率が10倍いい。
3. **返信率の悪化は致命的。** 半分になると19ヶ月遅れる。
   だから送る文面より「誰に送るか」に設計を寄せる（→ `docs/03-acquisition.md`）。

**この3点から、価格を先に決めて、その価格が通る相手だけに送る、という順序で設計する。**
安く売って数で埋めるルートは、シミュレータ上で明確に破綻する。

## 何を売るのか

> **求人に出ている定型業務を、AIで自動化して月額で運用代行する。**

売り物は「ツール」ではなく「その業務がもう発生しない状態」。
ツールとして売ると月額3万円の相場に引きずられるが、業務の代替として売ると
削減できる人件費が価格の基準になり、月額15〜50万円が通る。

### 具体的な対象業務

| 業務 | よくある状態 | 削減できる工数 |
|---|---|---|
| 受注処理 | メール/FAX/PDFの注文を基幹システムへ手入力 | 月60〜120時間 |
| 請求・支払突合 | 請求書とシステムの金額を目視で照合 | 月40〜80時間 |
| 問い合わせ一次対応 | 定型質問に人が毎回返信 | 月50〜100時間 |
| 応募者・顧客データ整理 | 複数媒体のデータを手で名寄せ | 月30〜60時間 |

### 価格の根拠

月80時間の作業 × 人件費2,000円/時 = **月16万円の直接コスト**。
これに採用コスト・教育コスト・退職リスクが乗る。
月額15万円は「派遣を1人雇うより安い」という比較で通る価格であり、
相見積もりを取られにくい（比較対象がSaaSではなく人件費になるため）。

## なぜこのルートなのか

現状のアセットは **開発力のみ**（法人格なし・実績なし・人脈なし・フォロワーなし）で、
制約は **週12時間・資金100万円**。この条件に対して、このルートは4つ噛み合っている。

1. **唯一のアセットである開発力が、そのまま原価ゼロの粗利になる。**
   粗利率85%はソフトウェアだからこそ成立する。物販なら20〜30%で、同じ日給に
   3〜4倍の売上が必要になる。
2. **求人票が、そのまま「困っている証拠」の公開リストになっている。**
   誰が今困っているかを会社自身が公開しているので、リスト作りが自動化できる。
   これが週12時間でも営業が回る唯一の理由。
3. **ROIを金額で示せるので、実績ゼロでも売れる。**
   「月92時間が4時間になります」は、ポートフォリオが無くても検証可能な主張になる。
4. **2社目以降の構築時間が半分になる。** 同業種なら業務構造がほぼ同じなので、
   1社目に8時間かけた仕組みが、2社目は3〜4時間で入る。工数が逓減する。

### 検討して外したルート

| ルート | 外した理由 |
|---|---|
| SEOブログ | 除外指定。加えて成果まで12〜18ヶ月、週12時間では記事数が積めない |
| 受託開発 | 労働集約。週12時間だと月50万円が構造上の天井で、止めれば収入もゼロになる |
| 自社SaaS（セルフサーブ） | 認知獲得に広告費が要る。資金100万円ではCAC回収前に尽きる |
| EC・物販 | 粗利率20〜30%。日給10万円に月商1,000万円以上が必要。在庫リスクも乗る |
| 広告アフィリエイト | 資金100万円ではテスト回数が足りない。媒体のBANで即ゼロになる |
| 情報商材・スクール | 短期の現金化は早いが、実績ゼロで始めると信用の借金になり、2年目が無い |

受託開発だけは**完全には外さない**。実績ゼロの状態を最短で抜けるために、
最初の2〜3件だけスポットの自動化案件として受ける（→ `docs/01-roadmap.md` フェーズ0）。
ただしこれは実績づくりの手段であって、事業の柱にはしない。

## 制約から逆算した設計方針

週12時間＝月52時間しかない。この中で営業と構築の両方を回すには、次の割り振りしか成立しない。

| 用途 | 月あたり | 方針 |
|---|---|---|
| 営業システムの運用 | 8時間 | 全自動化。手を動かすのは返信が来たときだけ。**リスト作成は外注**（月2.5万円） |
| 商談 | 8時間 | 1社30分 × 16回。初回で提案まで終わらせる |
| 構築・納品 | 30時間 | 1社8時間 × 月2〜3社。横展開で逓減させる |
| 数字の確認と改善 | 6時間 | 週1回30分のダッシュボード確認 |

営業に月8時間しか割けないことが、`src/cashman/` の設計をすべて決めている。
リスト作り・文面生成・送信・フォロー・配信停止処理は、全部コードが持つ。
人間が判断するのは「返信が来た相手にどう返すか」だけに絞る。

**10ヶ月目に、この52時間が必ず埋まる**（シミュレータ上では顧客18社の時点）。
そこが専業化か外注かを決める分岐点で、ロードマップはその分岐を前提に組んである。
